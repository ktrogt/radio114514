# RC（ラジコン化）

最終更新: 2026-10-31（Claude Code が記録）

RoboCup Junior サッカーロボット（Gcraud-Shuffle、メイン基板 F446）に載っている XIAO ESP32S3 を使い、ロボットをラジコンとして操作する。
操作は PC のキーボード・スマホのスティック画面・コントローラー（ブラウザ経由、または BLE ゲームパッドを直接）でできる。

```
PC / スマホ（ブラウザ） ─Wi-Fi─┐
                                ├─ ESP32（XIAO ESP32S3） ─UART4─ F446（メイン）
BLE ゲームパッド ─────BLE─┘
```

このリポジトリ（https://github.com/ktrogt/radio114514 、公開）は、チームのリポジトリ Gcraud-Shuffle-2026 の `RC/` フォルダを独立させたもの。
開発用の PC では `C:\Users\ktrog\git\Gcraud-Shuffle-2026\RC` に置いている（チームのリポジトリ側では、この PC の `.git/info/exclude` で `/RC/` を除外している）。

| フォルダ | 中身 |
|---|---|
| `Firmware/` | F446 のファーム。STM32CubeIDE プロジェクト `rc_2026`（`main/Firmware` を複製して作った別プロジェクト） |
| `ESP32/rc_esp32/` | ESP32 のファーム（Arduino スケッチ） |
| `ESP32/web/` | 操作画面（HTML/CSS/JS）。ESP32 に埋め込んで配信する |
| `Common/` | F446 と ESP32 の通信形式（`rc_protocol.h`）と共通の上限値（`rc_shared_config.h`） |
| `tools/sync_esp32.mjs` | `Common/` の写しと操作画面を、ESP32 のスケッチに取り込むツール |
| `tests/` | 通信形式と操作画面のテスト（Node.js） |

## 使い方

### 1. F446 に書き込む
1. STM32CubeIDE で File → Import → Existing Projects into Workspace を選び、このリポジトリの `Firmware` を取り込む（プロジェクト名 `rc_2026`）。「Copy projects into workspace」は外す。
   試合用の `main_2026` とは別のプロジェクトとして並ぶ。
2. 機体を確認する。`Firmware/Core/Inc/rc_config_f446.h` の `RC_HARDWARE_PROFILE` は、今は KURO になっている。SIRO に書くときは `RC_PROFILE_SIRO` にする。
3. ビルドして、`rc_2026 Debug.launch` で書き込む。

### 2. ESP32 に書き込む
1. 初めてのときだけ: `ESP32/rc_esp32/rc_secrets.example.h` を同じフォルダに `rc_secrets.h` という名前で複製し、`RC_AP_PASSWORD`（ロボットの Wi-Fi のパスワード、8 文字以上）を書く。
   `rc_secrets.h` は git の対象外（このリポジトリは公開なので、パスワードは載せない）。ないとビルドがエラーで止まる。
2. Arduino IDE で `ESP32/rc_esp32/rc_esp32.ino` を開く。
3. ボードは「esp32_bluepad32」の **XIAO_ESP32S3** を選ぶ（「esp32」の方ではない）。Upload Speed は 115200。
4. そのまま書き込む。書き込んだあとは、開いている操作画面を読み込み直す（PC は Ctrl+Shift+R）。

### 3. PC から操作する
1. ロボットの電源を入れる。
2. PC の Wi-Fi で `GC-RC-xxxx`（xxxx は機体ごとに違う）につなぐ。
   パスワードは、ESP32 に書き込んだときの `ESP32/rc_esp32/rc_secrets.h` の `RC_AP_PASSWORD`。
3. ブラウザで `http://192.168.4.1/` を開き、画面をクリックする。
4. 赤スイッチで有効にする。キーを全部離した状態から操作を始める。

| 操作 | キー |
|---|---|
| 移動（フィールド基準） | W 前 / S 後 / A 左 / D 右 |
| 向き | Q 左 / E 右（押している間は「前」から 45° 左／右を向き、離すと「前」に戻る） |
| キック | Space |
| ドリブラー 有効 / 無効 | F |
| 正面リセット（今の向きを「前」にする） | R（移動・旋回キーを離した状態で） |
| ライン補助 有効 / 無効 | G（最初は無効。ラインセンサーのしきい値がフィールドに合っていないため） |
| ブースト / 低速 | Shift / C（両方押すと低速） |
| 停止 / 解除 | Esc（画面の「停止」ボタンも同じ） |

- 「前」は、電源を入れたときにロボットが向いていた方向。R か、モーター無効のときの緑スイッチの短押しで、今の向きに変えられる。
- 速さの上限は試合の 80%（ブーストで 100%、低速で 40%）。
- 向きの操作は、倒した量に応じた角度を向く（いっぱいで「前」から 45°）。離すと「前」に戻る。
  キー・スマホ・ゲームパッドとも、倒し始めの 25% は遊び（反応しない範囲）。
- 止め方: キーを離す / Esc / 赤スイッチ。Wi-Fi やブラウザが切れても 0.3 秒以内に止まる。
- いったん止まったら、キーを全部離すまで動かない。止まるとドリブラーも切れるので、F で入れ直す。
- ライン基板と通信できないと、ライン補助が有効な間は動かない。そのときは G でライン補助を切る。
- ライン補助を有効にすると、側面センサーが反応した方向（左・右・後ろ）へは動かない。
  今はしきい値がフィールドに合っておらず誤反応するので、最初は無効にしてある。
  しきい値を直したら、`Common/rc_shared_config.h` の `RC_LINE_ASSIST_DEFAULT` を 1 にすれば、最初から有効になる。

### 3b. スマホから操作する（スティック画面）
1. スマホをロボットの Wi-Fi `GC-RC-xxxx` につなぎ、`http://192.168.4.1/` を開いて画面をタップする。
   スマホでは最初からスティック画面になる（画面右上の「キーボード｜スティック」で切り替えられ、選んだ方を覚えている）。
2. 横向きで使うのがおすすめ。
3. 操作できるブラウザは同時に 1 台だけ。PC で同じページを開いているときは閉じる。

| 操作 | スティック画面 |
|---|---|
| 速さ | 左スティックの上下。上下にずらした分だけ変わり、指を離しても残る（最初は 50%） |
| 向き | 左スティックの左右。倒した量に応じて「前」から最大 45° 左右を向く。指を離すと「前」に戻る。中央付近は遊び |
| 移動（フィールド基準） | 右スティック。倒した方向へ、倒した量 × 速さで動く。指を離すと止まる |
| キック / ドリブラー / 正面リセット / ライン補助 / 停止 | 中央のボタン |

- 速さ 100% で右スティックをいっぱいに倒すと、試合の最大の速さになる。
- 画面を消す、別のアプリに切り替える、指を離す、のいずれでも止まる。

### 3c. iPhone を中継してコントローラーで操作する（PXN-9607X など）
ロボットに直接つながらないコントローラー（Switch モードの PXN-9607X など）は、iPhone を中継にして使う。
1. iPhone の「設定」→「Bluetooth」で、コントローラーをペアリングする（PXN は電源を入れると Switch モードでペアリング待ちになる）。
2. iPhone の「設定」→「画面表示と明るさ」→「自動ロック」を「なし」にしておく。画面が消えると、ロボットは止まる。
3. iPhone をロボットの Wi-Fi `GC-RC-xxxx` につなぎ、Safari で `http://192.168.4.1/` を開いて画面をタップする。
4. コントローラーのボタンを 1 回押す（iPhone はボタンを押すまでコントローラーをページに見せない）。認識すると、自動で「コントローラー」モードになり、名前が表示される。
5. 赤スイッチで有効にして操作する。

| 操作 | コントローラー（ボタンは位置で決まる） |
|---|---|
| 移動 | 左スティック |
| 向き | 右スティックの左右 |
| キック | 下のボタン（Switch: B / Xbox: A）か ZR / RT |
| ドリブラー | 右のボタン（Switch: A / Xbox: B） |
| ライン補助 | 左のボタン（Switch: Y / Xbox: X） |
| 正面リセット | 上のボタン（Switch: X / Xbox: Y） |
| ブースト / 低速 | R / ZL（押している間） |
| 停止 / 解除 | − |

- Safari を閉じる、画面が消える、コントローラーが切れる、のいずれでも止まる。
- 画面が戻ったときやモードを切り替えたときは、スティックをいったん中央に戻すまで動かない（ボタンもいったん離すまで効かない）。

### 4. ゲームパッドで操作する（入手後）
- 使える機種: Xbox ワイヤレスコントローラー 1914（現行型。ファーム 5.15 以上）が第一候補。
  PS4/PS5/Switch Pro は XIAO ESP32S3 では使えない（Bluetooth Classic のため）。
- 登録:
  1. モーターが無効の状態で、緑スイッチを 3 秒押し続ける。ブザーが鳴り、30 秒間だけ登録を受け付ける。
  2. その間にゲームパッドのペアリングボタンを押す。
  3. 最初につながった 1 台が登録される。以後は登録した 1 台だけがつながる。
- ゲームパッドがつながっているときは、ゲームパッドが優先される。

| 操作 | ゲームパッド |
|---|---|
| 移動 | 左スティック |
| 向き | 右スティックの左右（倒した量に応じた角度。離すと「前」に戻る） |
| キック | A か ZR / RT |
| ドリブラー 有効 / 無効 | B |
| 正面リセット | Y |
| ライン補助 有効 / 無効 | X |
| ブースト / 低速 | RB を押している間 / LT を半分以上引いている間 |
| 停止 / 解除 | View（Back） |

## 最初の実機確認（推奨する順番）
コードの上では試合用と同じ向きにしてあるが、実機ではまだ一度も動かしていない。

1. 車輪を床から浮かせて、赤スイッチで有効にする。
2. 画面の「向き」を見ながらロボットを手で時計回りに回し、値が増えることを確かめる（時計回りが＋）。
   逆なら `rc_config_f446.h` の `RC_RAW_YAW_TO_CW` の符号を変える。
3. W・D・Q・E を押し、車輪がそれぞれ前進・右・左回り・右回りの向きに回ることを確かめる。
4. ブラウザのタブを切り替える、PC の Wi-Fi を切る、赤スイッチを押す、の 3 通りで止まることを確かめる。
5. 床に置いて低速（C を押したまま）で動かす。手で向きをずらし、元の向きに戻ろうとすることを確かめる。
6. キック（Space）とドリブラー（F）を確かめる。
7. 白線に近づけて、場外に向かう動きだけが止まることを確かめる。

## 経緯と決定事項（記録）

### ユーザーの要望（2026-10-13、ユーザー本人から）
- 試合用の既存プロジェクトとは分けて、新しいプロジェクトとして作る。形は今と同じ（F446 の STM32CubeIDE プロジェクト）。
- 作るもの: メイン（F446）のプログラム、ESP32 のプログラム、PC の操作 UI（ミニマム、キーボードで操作）。
- 最終的にコントローラーで操作するとき、プログラムの変更が要らないか、軽微な変更で済む構成にする。
- 最終的なコントローラー: 市販の BLE ゲームパッド（手元にはまだない）。
- 操作方式: フィールド基準＋向き保持（ジャイロ）。
- 操作する機能: 移動・回転、ドリブラー、キック、場外に出ない補助（ラインセンサー）。
- 最初にラジコン化する機体は KURO。
- 実作業は Codex（gpt-6.1-sol, xhigh）に任せる。

### 決定事項
- 置き場所: このリポジトリの `RC/`。既存の `main/Firmware` と `Communication` は変更しない。コミットはユーザーの指示があるまでしない。
- ESP32 は、PC とゲームパッドのどちらの入力も「仮想ゲームパッド（スティックとボタン）」の形にそろえてから、F446 へのコマンドに変換する。
  F446 は入力元を区別しない。ゲームパッドに替えても F446 側と変換処理は変えずに済む。
- PC とのやり取りは Wi-Fi にし、BLE はゲームパッド用に空けておく。
- PC の操作画面は、ESP32 が配信するブラウザのページにする。インストールは要らない（この PC には Python が入っていない）。
- RC 用のファームを書き込むと、ESP32 のロボット間通信（`Communication/Central`, `Peipheral`）と F446 の試合用ファームは上書きされる。試合に戻すときは書き直す。
- 安全（Claude が既定値として決めた。ユーザー未確認）:
  - 赤スイッチで有効と無効を切り替える（試合用と同じトグル）。
  - ESP32 からのコマンドが 0.3 秒途切れたら止まる（F446 の 1 ms ごとの割り込みでも確かめている）。
  - いったん止まったら、操作が中立になるまで動かない。止まるとドリブラーも切れる。
  - 公式通信モジュールの PLAY 信号は使わない。
- 通信: F446↔ESP32 は 115200bps。同期バイト・版・連番・CRC-8 付きのフレームを使う。コマンドは 50 Hz、状態の返信は 10 Hz。
  - キックと正面リセットは、押した回数のカウンタで送る。フレームが欠けても二重に動かず、取りこぼさない。
  - ESP32 の再起動で誤ってキックしないよう、通信が途切れたあとの最初のフレームでは、カウンタを基準に取り直すだけにする。
- 操作元:
  - ゲームパッドは、つながっている間は有効とみなす。BLE のゲームパッドは変化があったときしか送らないことが多いので、データの間隔では判断しない。
  - 電波が切れたことは BLE の監視タイムアウトで検出する。BTstack の既定値 0.72 秒を要求し、ゲームパッド側からの変更は 1 秒までしか受け入れない。
  - ブラウザは、0.2 秒入力が届かないと操作元から外れる。
  - 操作元が替わるときは 0.1 秒以上止め、新しい操作元はスティックやキーが中立のときだけ操作を取れる。
- 場外に出ない補助: ラインを見つけた瞬間の「外向き」の方向を覚え、その方向へ進む成分だけを消す。
  ライン上で逆向きの値が出ても（ラインの中心を越えたとき）、覚えた向きを使う。左右と後ろの側面センサーが反応した方向へも進まない。
  これは補助にすぎず、勢いや押し合いで外に出ることは防げない。

### 調査結果（2026-10-13、Codex が調査し Claude が確認。詳細の出典は `~/.claude/codex-runs/20261013-150610.*`）
- Bluepad32 は Arduino の「ESP32 + Bluepad32」ボードパッケージ 4.1.0 で使える（中身は Arduino-ESP32 2.0.17 と BTstack 1.6.1）。ボードの定義に `XIAO_ESP32S3` がある。
  Boards Manager の URL: `https://raw.githubusercontent.com/ricardoquesada/esp32-arduino-lib-builder/master/bluepad32_files/package_esp32_bluepad32_index.json`
- Wi-Fi の SoftAP と BLE の同時使用は、Espressif の資料では「対応しているが性能は不安定になりうる」扱い。
  インストールしたパッケージでは共存機能（`CONFIG_ESP32_WIFI_SW_COEXIST_ENABLE=1`）が有効。実機での遅延と安定性は未確認。
- 使えるゲームパッドの出典: https://github.com/ricardoquesada/bluepad32/blob/4.1.0/docs/supported_gamepads.md
- 既存の試合用コードについて分かったこと:
  - 旋回の制御は PD（Kp 0.6, Kd 1.0）で、出力に −18 を掛けて ±800 で制限している。RC でも同じ値を使う（上限は速度の設定に応じて下げる）。
  - キックは約 150 ms 出力したあと、約 1 秒のクールダウンを入れる（TIM7 は 1 カウント約 0.5 ms）。
  - ライン基板からのデータは USART6 で受ける。`LineDepth` の単位は mm ではない。
  - STM32CubeIDE は `.eclipseproduct` では 1.18.1、`stm32cubeide.ini` ではビルド ID 2.0.0 と書かれていて、実際の版ははっきりしない。

- 2026-10-13 実機での最初の試験（ユーザー）:
  - ESP32 は書き込めた。PC・スマホから Wi-Fi とページにはつながった。
    操作できるブラウザは同時に 1 台なので、スマホがつながっている間は PC が「再接続中」になる。
  - 「ロボット未接続」のまま、F446 から返事がなかった。
    Claude の見立て: F446 が起動直後にジャイロ（BNO055）を初期化して失敗し、`Error_Handler` で止まっていた。BNO055 は電源投入から約 650 ms は応答しない。
  - Claude が F446 を直した。
    - 起動後 0.7 秒待ってからジャイロを初期化する。失敗しても止まらず、0.5 秒ごとにやり直し、その間は「ジャイロ異常」として返事を返し続ける。
